  SECTION: [Host](#section-3.2.2)

    TEXT[implementation,test]:    insensitive.
    TEXT[implementation]:       host        = IP-literal / IPv4address / reg-name
    TEXT[implementation,test]:    If host matches the rule for IPv4address, then it should be
    TEXT[implementation,test]:    considered an IPv4 address literal and not a reg-name.
    TEXT[implementation]: Although host
    TEXT[implementation]:    is case-insensitive, producers and normalizers should use lowercase
    TEXT[implementation]:    for registered names and hexadecimal addresses for the sake of

    TEXT[implementation]:       IP-literal = "[" ( IPv6address / IPvFuture  ) "]"
    TEXT[implementation]:       IPvFuture  = "v" 1*HEXDIG "." 1*( unreserved / sub-delims / ":" )
    TEXT[test]:    A 128-bit IPv6 address is divided into eight 16-bit pieces.
    TEXT[implementation]:       IPv6address =                            6( h16 ":" ) ls32
    TEXT[implementation]:                   /                       "::" 5( h16 ":" ) ls32
    TEXT[implementation]:                   / [               h16 ] "::" 4( h16 ":" ) ls32
    TEXT[implementation]:                   / [ *1( h16 ":" ) h16 ] "::" 3( h16 ":" ) ls32
    TEXT[implementation]:                   / [ *2( h16 ":" ) h16 ] "::" 2( h16 ":" ) ls32

    TEXT[implementation]:                   / [ *4( h16 ":" ) h16 ] "::"              ls32
    TEXT[implementation]:                   / [ *5( h16 ":" ) h16 ] "::"              h16
    TEXT[implementation]:                   / [ *6( h16 ":" ) h16 ] "::"

    TEXT[implementation]:                   / "2" %x30-34 DIGIT     ; 200-249
    TEXT[implementation]:                   / "25" %x30-35          ; 250-255

    TEXT[implementation]:    label of a fully qualified domain name in DNS may be followed by a
    TEXT[implementation]:    single "." and should be if it is necessary to distinguish between
    TEXT[implementation]:    the complete domain name and some local domain.

    TEXT[implementation,test]:    components and subcomponents prior to decoding the octets, as
    TEXT[implementation,test]:    otherwise the decoded octets might be mistaken for delimiters.
    TEXT[implementation]:    Security checks of the data within a URI should be applied after

    TEXT[implementation,test]:    can become a security concern if an application attempts to filter

  SECTION: [Rule Naming](#section-2.1)
    TEXT[test]:    The name of a rule is simply the name itself, that is, a sequence of
    TEXT[test]:    characters, beginning with an alphabetic character, and followed by a
    TEXT[test]:    combination of alphabetics, digits, and hyphens (dashes).
    TEXT[implementation]:       Rule names are case insensitive.
    TEXT[test]:    The names <rulename>, <Rulename>, <RULENAME>, and <rUlENamE> all
    TEXT[test]:    refer to the same rule.

  SECTION: [Rule Form](#section-2.2)
    TEXT[test]:    For visual ease, rule definitions are left aligned.  When a rule
    TEXT[test]:    requires multiple lines, the continuation lines are indented.

  SECTION: [Terminal Values](#section-2.3)
    TEXT[implementation]: In ABNF, a character is merely a non-negative integer.
    TEXT[test]:          CR          =  %d13
    TEXT[test]:          CR          =  %x0D
    TEXT[test]:          CRLF        =  %d13.10
    TEXT[test]:          command     =  "command string"
    TEXT[test]:    will match only the string that comprises only the lowercase
    TEXT[test]:    characters, abc.

  SECTION: [Concatenation:  Rule1 Rule2](#section-3.1)
    TEXT[implementation]:    A rule can define a simple, ordered string of values (i.e., a
    TEXT[implementation]:    concatenation of contiguous characters) by listing a sequence of rule
    TEXT[implementation]:    names.
    TEXT[test]:          mumble      =  foo bar foo

  SECTION: [Alternatives:  Rule1 / Rule2](#section-3.2)
    TEXT[implementation]:    Elements separated by a forward slash ("/") are alternatives.

  SECTION: [Incremental Alternatives: Rule1 =/ Rule2](#section-3.3)
    TEXT[implementation]: That is, an initial rule may match one or more
    TEXT[implementation]:    alternatives, with later rule definitions adding to the set of
    TEXT[implementation]:    alternatives.
    TEXT[test]:          ruleset     =  alt1 / alt2
    TEXT[test]:          ruleset     =/ alt3
    TEXT[test]:          ruleset     =/ alt4 / alt5
    TEXT[implementation]:          ruleset     =  alt1 / alt2 / alt3 / alt4 / alt5

  SECTION: [Value Range Alternatives:  %c##-##](#section-3.4)
    TEXT[test]:          DIGIT       =  %x30-39
    TEXT[implementation]:    Concatenated numeric values and numeric value ranges cannot be
    TEXT[implementation]:    specified in the same string.
    TEXT[test]:          char-line = %x0D.0A %x20-7E %x0D.0A

  SECTION: [Sequence Group:  (Rule1 Rule2)](#section-3.5)
    TEXT[test]:    matches (elem foo blat) or (elem bar blat), and
    TEXT[test]:    matches (elem foo) or (bar blat).
    TEXT[test]:         (elem foo) / (bar blat)

  SECTION: [Variable Repetition:  *Rule](#section-3.6)
    TEXT[implementation]:          <a>*<b>element
    TEXT[implementation]:    where <a> and <b> are optional decimal values, indicating at least
    TEXT[implementation]:    <a> and at most <b> occurrences of the element.
    TEXT[implementation,test]:    Default values are 0 and infinity
    TEXT[test]:  so that *<element> allows any
    TEXT[test]:    number, including zero; 1*<element> requires at least one;
    TEXT[test]:    3*3<element> allows exactly 3; and 1*2<element> allows one or two.

  SECTION: [Specific Repetition:  nRule](#section-3.7)
    TEXT[implementation,test]:    That is, exactly <n> occurrences of <element>.
    TEXT[test]:   Thus, 2DIGIT is a
    TEXT[test]:    2-digit number, and 3ALPHA is a string of three alphabetic
    TEXT[test]:    characters.

  SECTION: [Optional Sequence:  [RULE]](#section-3.8)
    TEXT[implementation]:    Square brackets enclose an optional element sequence:
    TEXT[test]:          [foo bar]
    TEXT[test]:    is equivalent to
    TEXT[test]:          *1(foo bar).

  SECTION: [Comment:  ; Comment](#section-3.9)
    TEXT[test]:    A semicolon starts a comment that continues to the end of line.

  SECTION: [ABNF Definition of ABNF](#section-4)
    TEXT[implementation]: This syntax requires a formatting of rules that is relatively
    TEXT[implementation]:           strict.  Hence, the version of a ruleset included in a
    TEXT[implementation]:           specification might need preprocessing to ensure that it can
    TEXT[implementation]:           be interpreted by an ABNF parser.
    TEXT[implementation,test]:          rulelist       =  1*( rule / (*c-wsp c-nl) )
    TEXT[implementation]:          rule           =  rulename defined-as elements c-nl
    TEXT[implementation,test]:          rulename       =  ALPHA *(ALPHA / DIGIT / "-")
    TEXT[implementation]:          defined-as     =  *c-wsp ("=" / "=/") *c-wsp
    TEXT[implementation]:                                 ; basic rules definition and
    TEXT[implementation]:                                 ;  incremental alternatives
    TEXT[implementation]:          c-wsp          =  WSP / (c-nl WSP)
    TEXT[implementation]:          c-nl           =  comment / CRLF
    TEXT[implementation,test]:          comment        =  ";" *(WSP / VCHAR) CRLF
    TEXT[implementation]:          alternation    =  concatenation
    TEXT[implementation]:                            *(*c-wsp "/" *c-wsp concatenation)
    TEXT[implementation]:          concatenation  =  repetition *(1*c-wsp repetition)
    TEXT[implementation]:          repetition     =  [repeat] element
    TEXT[implementation]:          repeat         =  1*DIGIT / (*DIGIT "*" *DIGIT)
    TEXT[implementation]:          element        =  rulename / group / option /
    TEXT[implementation]:                            char-val / num-val / prose-val
    TEXT[implementation]:          group          =  "(" *c-wsp alternation *c-wsp ")"
    TEXT[implementation]:          option         =  "[" *c-wsp alternation *c-wsp "]"
    TEXT[implementation]:          num-val        =  "%" (bin-val / dec-val / hex-val)
    TEXT[implementation,test]:          prose-val      =  "<" *(%x20-3D / %x3F-7E) ">"

  SECTION: [Core Rules](#appendix-B.1)
    TEXT[implementation,test]:    Certain basic rules are in uppercase, such as SP, HTAB, CRLF, DIGIT,
    TEXT[implementation,test]:    ALPHA, etc.

  SECTION: [A Recommendation for IPv6 Text Representation](#section-4)
    TEXT[!MUST]: The recommendation
    TEXT[!MUST]:    in this section SHOULD be followed by systems when generating an
    TEXT[!MUST]:    address to be represented as text, but all implementations MUST
    TEXT[!MUST]:    accept and be able to handle any legitimate [RFC4291] format.

  SECTION: [Handling Leading Zeros in a 16-Bit Field](#section-4.1)
    TEXT[!MUST]:    Leading zeros MUST be suppressed.
    TEXT[!MUST]: A single 16-
    TEXT[!MUST]:    bit 0000 field MUST be represented as 0.

  SECTION: [Shorten as Much as Possible](#section-4.2.1)
    TEXT[!MUST,implementation,test]:    The use of the symbol "::" MUST be used to its maximum capability.
    TEXT[test]:    For example, 2001:db8:0:0:0:0:2:1 must be shortened to 2001:db8::2:1.
    TEXT[test]:    Likewise, 2001:db8::0:1 is not acceptable, because the symbol "::"
    TEXT[test]:    could have been used to produce a shorter representation 2001:db8::1.

  SECTION: [Handling One 16-Bit 0 Field](#section-4.2.2)
    TEXT[!MUST,implementation,test]:    The symbol "::" MUST NOT be used to shorten just one 16-bit 0 field.

  SECTION: [Choice in Placement of "::"](#section-4.2.3)
    TEXT[!MUST,implementation,test]:    When there is an alternative choice in the placement of a "::", the
    TEXT[!MUST,implementation,test]:    longest run of consecutive 16-bit 0 fields MUST be shortened (i.e.,
    TEXT[!MUST,implementation,test]:    the sequence with three consecutive zero fields is shortened in 2001:
    TEXT[!MUST,implementation,test]:    0:0:1:0:0:0:1).
    TEXT[!MUST,implementation,test]: When the length of the consecutive 16-bit 0 fields
    TEXT[!MUST,implementation,test]:    are equal (i.e., 2001:db8:0:0:1:0:0:1), the first sequence of zero
    TEXT[!MUST,implementation,test]:    bits MUST be shortened.

  SECTION: [Lowercase](#section-4.3)
    TEXT[!MUST]:    The characters "a", "b", "c", "d", "e", and "f" in an IPv6 address
    TEXT[!MUST]:    MUST be represented in lowercase.

  SECTION: [Text Representation of Special Addresses](#section-5)

    TEXT[!SHOULD,implementation,test]:    RECOMMENDED if the following condition is met: the address can be
    TEXT[!SHOULD,implementation,test]:    distinguished as having IPv4 addresses embedded in the lower 32 bits
    TEXT[!SHOULD,implementation,test]:    solely from the address field through the use of a well-known prefix.
    TEXT[implementation]:    Such prefixes are defined in [RFC4291] and [RFC2765] at the time of
    TEXT[implementation]:    this writing.
    TEXT[!MAY]: If it is known by some external method that a given

    TEXT[!MAY]:    notation.
    TEXT[implementation,test]:    The text representation method noted in Section 4 should be applied

  SECTION: [Header List Ordering](#section-2.1)
    TEXT[!MUST,implementation,test]:    An encoder MUST order header field representations in the header
    TEXT[!MUST,implementation,test]:    block according to their ordering in the original header list.
    TEXT[!MUST,implementation,test]:    decoder MUST order header fields in the decoded header list according
    TEXT[!MUST,implementation,test]:    to their ordering in the header block.

  SECTION: [Dynamic Table](#section-2.3.2)
    TEXT[implementation]:    The dynamic table is initially empty.
    TEXT[!MUST,implementation,test]: Therefore, duplicate entries MUST NOT
    TEXT[!MUST,implementation,test]:    be treated as an error by a decoder.

  SECTION: [Index Address Space](#section-2.3.3)
    TEXT[implementation]:    Indices between 1 and the length of the static table (inclusive)
    TEXT[implementation]:    refer to elements in the static table (see Section 2.3.1).
    TEXT[implementation]:    Indices strictly greater than the length of the static table refer to
    TEXT[implementation]:    elements in the dynamic table (see Section 2.3.2).  The length of the
    TEXT[implementation]:    static table is subtracted to find the index into the dynamic table.
    TEXT[!MUST,implementation]:    Indices strictly greater than the sum of the lengths of both tables
    TEXT[!MUST,implementation]:    MUST be treated as a decoding error.

  SECTION: [Header Field Representation Processing](#section-3.2)
    TEXT[!MUST,implementation]: To ensure that the decoding will successfully
    TEXT[!MUST,implementation]:    produce a header list, a decoder MUST obey the following rules.

  SECTION: [Calculating Table Size](#section-4.1)
    TEXT[implementation]:    The size of an entry is the sum of its name's length in octets (as
    TEXT[implementation]:    defined in Section 5.2), its value's length in octets, and 32.

  SECTION: [Maximum Table Size](#section-4.2)
    TEXT[!MUST,implementation,test]:    An encoder can choose to use less capacity than this maximum size
    TEXT[!MUST,implementation,test]:    (see Section 6.3), but the chosen size MUST stay lower than or equal
    TEXT[!MUST,implementation,test]:    to the maximum set by the protocol.
    TEXT[!MUST,implementation]: This dynamic table size
    TEXT[!MUST,implementation]:    update MUST occur at the beginning of the first header block
    TEXT[!MUST,implementation]:    following the change to the dynamic table size.
    TEXT[!MUST,implementation,test]: In the case that this size is
    TEXT[!MUST,implementation,test]:    changed more than once in this interval, the smallest maximum table
    TEXT[!MUST,implementation,test]:    size that occurs in that interval MUST be signaled in a dynamic table
    TEXT[!MUST,implementation,test]:    size update.

  SECTION: [Entry Eviction When Dynamic Table Size Changes](#section-4.3)
    TEXT[implementation]:    Whenever the maximum size for the dynamic table is reduced, entries
    TEXT[implementation]:    are evicted from the end of the dynamic table until the size of the
    TEXT[implementation]:    dynamic table is less than or equal to the maximum size.

  SECTION: [Entry Eviction When Adding New Entries](#section-4.4)
    TEXT[implementation]:    Before a new entry is added to the dynamic table, entries are evicted
    TEXT[implementation]:    from the end of the dynamic table until the size of the dynamic table
    TEXT[implementation]:    is less than or equal to (maximum size - new entry size) or until the
    TEXT[implementation]:    table is empty.
    TEXT[implementation]:    If the size of the new entry is less than or equal to the maximum
    TEXT[implementation]:    size, that entry is added to the table.  It is not an error to
    TEXT[implementation]:    attempt to add an entry that is larger than the maximum size; an
    TEXT[implementation]:    attempt to add an entry larger than the maximum size causes the table
    TEXT[implementation]:    to be emptied of all existing entries and results in an empty table.

  SECTION: [Integer Representation](#section-5.1)
    TEXT[implementation]:    This integer representation allows for values of indefinite size.  It
    TEXT[implementation]:    is also possible for an encoder to send a large number of zero
    TEXT[implementation]:    values, which can waste octets and could be used to overflow integer
    TEXT[implementation]:    values.
    TEXT[!MUST,implementation,test]: Integer encodings that exceed implementation limits -- in
    TEXT[!MUST,implementation,test]:    value or octet length -- MUST be treated as decoding errors.

  SECTION: [String Literal Representation](#section-5.2)
    TEXT[implementation]:    Upon decoding, an incomplete code at the end of the encoded data is
    TEXT[implementation]:    to be considered as padding and discarded.
    TEXT[!MUST,implementation,test]: A padding strictly longer
    TEXT[!MUST,implementation,test]:    than 7 bits MUST be treated as a decoding error.
    TEXT[!MUST,implementation,test]: A padding not
    TEXT[!MUST,implementation,test]:    corresponding to the most significant bits of the code for the EOS
    TEXT[!MUST,implementation,test]:    symbol MUST be treated as a decoding error.
    TEXT[!MUST,implementation,test]: A Huffman-encoded string
    TEXT[!MUST,implementation,test]:    literal containing the EOS symbol MUST be treated as a decoding
    TEXT[!MUST,implementation,test]:    error.

  SECTION: [Indexed Header Field Representation](#section-6.1)
    TEXT[implementation]:    The index value of 0 is not used.
    TEXT[!MUST,implementation]: It MUST be treated as a decoding
    TEXT[!MUST,implementation]:    error if found in an indexed header field representation.

  SECTION: [Literal Header Field Never Indexed](#section-6.2.3)

    TEXT[!MUST,exception]:    for encoding this header field.
    TEXT[!MUST,implementation]:    When a header field is represented as a literal header field never
    TEXT[!MUST,implementation]:    indexed, it MUST always be encoded with this specific literal

    TEXT[!MUST,exception]: In particular, when a peer sends a header field that

    TEXT[!MUST,implementation]:    determined by the protocol using HPACK.
    TEXT[!MUST,implementation]: A value that exceeds this

    TEXT[!MUST]:    MUST NOT be sent on a connected stream and MUST be treated as a
    TEXT[!MUST]:    stream error (Section 5.4.2) if received.
    TEXT[!MUST,exception]: Correspondingly, a proxy MUST send a TCP segment
    TEXT[!MUST,exception]:    with the RST bit set if it detects an error with the stream or the
    TEXT[!MUST,exception]:    HTTP/2 connection.

  SECTION: [Request Reliability](#section-8.7)
    TEXT[!MAY,exception]:    Requests that have not been processed have not failed; clients MAY
    TEXT[!MAY,exception]:    automatically retry them, even those with non-idempotent methods.
    TEXT[!MUST]:    A server MUST NOT indicate that a stream has not been processed
    TEXT[!MUST]:    unless it can guarantee that fact.
    TEXT[!MUST,implementation,test]: If frames that are on a stream
    TEXT[!MUST,implementation,test]:    are passed to the application layer for any stream, then
    TEXT[!MUST,implementation,test]:    REFUSED_STREAM MUST NOT be used for that stream, and a GOAWAY frame
    TEXT[!MUST,implementation,test]:    MUST include a stream identifier that is greater than or equal to the
    TEXT[!MUST,implementation,test]:    given stream identifier.

  SECTION: [Connection Management](#section-9.1)
    TEXT[!SHOULD,exception]:    Clients SHOULD NOT open more than one HTTP/2 connection to a given
    TEXT[!SHOULD,exception]:    host and port pair, where the host is derived from a URI, a selected
    TEXT[!SHOULD,exception]:    alternative service [ALT-SVC], or a configured proxy.
    TEXT[!SHOULD,exception]:    A client MAY open multiple connections to the same IP address and TCP
    TEXT[!SHOULD,exception]:    port using different Server Name Indication [TLS-EXT] values or to
    TEXT[!SHOULD,exception]:    provide different TLS client certificates but SHOULD avoid creating
    TEXT[!SHOULD,exception]:    multiple connections with the same configuration.
    TEXT[!SHOULD]: When either endpoint chooses to close the transport-layer
    TEXT[!SHOULD]:    TCP connection, the terminating endpoint SHOULD first send a GOAWAY
    TEXT[!SHOULD]:    (Section 6.8) frame so that both endpoints can reliably determine
    TEXT[!SHOULD]:    whether previously sent frames have been processed and gracefully
    TEXT[!SHOULD]:    complete or terminate any necessary remaining tasks.

  SECTION: [Connection Reuse](#section-9.1.1)
    TEXT[!MAY]:    Connections that are made to an origin server, either directly or
    TEXT[!MAY]:    through a tunnel created using the CONNECT method (Section 8.5), MAY
    TEXT[!MAY]:    be reused for requests with multiple different URI authority
    TEXT[!MAY]:    components.
    TEXT[!MUST]: The
    TEXT[!MUST]:    certificate presented by the server MUST satisfy any checks that the
    TEXT[!MUST]:    client would perform when forming a new TLS connection for the host
    TEXT[!MUST]:    in the URI.

  SECTION: [Use of TLS Features](#section-9.2)
    TEXT[!MUST]:    Implementations of HTTP/2 MUST use TLS version 1.2 [TLS12] or higher
    TEXT[!MUST]:    for HTTP/2 over TLS.
    TEXT[!SHOULD]: The general TLS usage guidance in [TLSBCP]
    TEXT[!SHOULD]:    SHOULD be followed, with some additional restrictions that are
    TEXT[!SHOULD]:    specific to HTTP/2.
    TEXT[!MUST]:    The TLS implementation MUST support the Server Name Indication (SNI)
    TEXT[!MUST]:    [TLS-EXT] extension to TLS.
    TEXT[!MUST,exception]: If the server is identified by a domain
    TEXT[!MUST,exception]:    name [DNS-TERMS], clients MUST send the server_name TLS extension
    TEXT[!MUST,exception]:    unless an alternative mechanism to indicate the target host is used.

  SECTION: [TLS 1.2 Features](#section-9.2.1)
    TEXT[!MAY]: An endpoint MAY immediately terminate an HTTP/2 connection that
    TEXT[!MAY]:    does not meet these TLS requirements with a connection error
    TEXT[!MAY]:    (Section 5.4.1) of type INADEQUATE_SECURITY.
    TEXT[!MUST]:    A deployment of HTTP/2 over TLS 1.2 MUST disable compression.
    TEXT[!MUST]:    A deployment of HTTP/2 over TLS 1.2 MUST disable renegotiation.
    TEXT[!MUST]: An
    TEXT[!MUST]:    endpoint MUST treat a TLS renegotiation as a connection error
    TEXT[!MUST]:    (Section 5.4.1) of type PROTOCOL_ERROR.
    TEXT[!MUST]:    An endpoint MAY use renegotiation to provide confidentiality
    TEXT[!MUST]:    protection for client credentials offered in the handshake, but any
    TEXT[!MUST]:    renegotiation MUST occur prior to sending the connection preface.
    TEXT[!SHOULD]:    server SHOULD request a client certificate if it sees a renegotiation
    TEXT[!SHOULD]:    request immediately after establishing a connection.
    TEXT[!MUST]:    Implementations MUST support ephemeral key exchange sizes of at least
    TEXT[!MUST]:    2048 bits for cipher suites that use ephemeral finite field Diffie-
    TEXT[!MUST]:    Hellman (DHE) (Section 8.1.2 of [TLS12]) and 224 bits for cipher
    TEXT[!MUST]:    suites that use ephemeral elliptic curve Diffie-Hellman (ECDHE)
    TEXT[!MUST]:    [RFC8422].
    TEXT[!MUST,exception]: Clients MUST accept DHE sizes of up to 4096 bits.
    TEXT[!MAY]:    Endpoints MAY treat negotiation of key sizes smaller than the lower
    TEXT[!MAY]:    limits as a connection error (Section 5.4.1) of type
    TEXT[!MAY]:    INADEQUATE_SECURITY.

  SECTION: [TLS 1.2 Cipher Suites](#section-9.2.2)
    TEXT[!SHOULD]:    A deployment of HTTP/2 over TLS 1.2 SHOULD NOT use any of the
    TEXT[!SHOULD]:    prohibited cipher suites listed in Appendix A.
    TEXT[!MAY]:    Endpoints MAY choose to generate a connection error (Section 5.4.1)
    TEXT[!MAY]:    of type INADEQUATE_SECURITY if one of the prohibited cipher suites is
    TEXT[!MAY]:    negotiated.
    TEXT[!MUST]:    Implementations MUST NOT generate this error in reaction to the
    TEXT[!MUST]:    negotiation of a cipher suite that is not prohibited.
    TEXT[!MUST]: To avoid this
    TEXT[!MUST]:    problem, which causes TLS handshake failures, deployments of HTTP/2
    TEXT[!MUST]:    that use TLS 1.2 MUST support TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256
    TEXT[!MUST]:    [TLS-ECDHE] with the P-256 elliptic curve [RFC8422].

  SECTION: [TLS 1.3 Features](#section-9.2.3)
    TEXT[!MUST]:    HTTP/2 servers MUST NOT send post-handshake TLS 1.3
    TEXT[!MUST]:    CertificateRequest messages.
    TEXT[!MUST,exception]: HTTP/2 clients MUST treat a TLS post-
    TEXT[!MUST,exception]:    handshake CertificateRequest message as a connection error
    TEXT[!MUST,exception]:    (Section 5.4.1) of type PROTOCOL_ERROR.
    TEXT[!MAY]:    TLS early data MAY be used to send requests, provided that the

  SECTION: [Cacheability of Pushed Responses](#section-10.4)
    TEXT[!MUST,exception]:    Where multiple tenants share space on the same server, that server
    TEXT[!MUST,exception]:    MUST ensure that tenants are not able to push representations of
    TEXT[!MUST,exception]:    resources that they do not have authority over.
    TEXT[!MUST,exception]:    Pushed responses for which an origin server is not authoritative (see
    TEXT[!MUST,exception]:    Section 10.1) MUST NOT be used or cached.

  SECTION: [Denial-of-Service Considerations](#section-10.5)
    TEXT[!SHOULD,exception]: A client that accepts server push SHOULD limit the number
    TEXT[!SHOULD,exception]:    of streams it allows to be in the "reserved (remote)" state.
    TEXT[implementation,test]: Providing tiny increments to flow control in WINDOW_UPDATE
    TEXT[implementation,test]:          frames can cause a sender to generate a large number of DATA
    TEXT[implementation,test]:          frames.
    TEXT[test]: An endpoint that constructs and remembers
    TEXT[test]:       frames for sending without considering TCP limits might be subject

    TEXT[implementation]:       changing settings, sending multiple undefined settings, or
    TEXT[implementation]:       changing the same setting multiple times in the same frame.
    TEXT[!SHOULD]: Implementations SHOULD track the use
    TEXT[!SHOULD]:    of these features and set limits on their use.
    TEXT[!MAY]: An endpoint MAY treat
    TEXT[!MAY]:    activity that is suspicious as a connection error (Section 5.4.1) of
    TEXT[!MAY]:    type ENHANCE_YOUR_CALM.

  SECTION: [Use of Compression](#section-10.6)
    TEXT[!MUST]:    Implementations communicating on a secure channel MUST NOT compress

    TEXT[!MUST]:    reliably determined.
    TEXT[!MUST]: Generic stream compression, such as that
    TEXT[!MUST]:    provided by TLS, MUST NOT be used with HTTP/2 (see Section 9.2).
